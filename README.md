# 顺序选择

用于按编号为参与者分配限量选项，运行环境为 Windows。目录内附带 Node.js，运行时使用项目内的文件。

## 启动

1. 编辑 UTF-8 编码的 `options.txt` 和 `people.txt`。
2. 运行 `.\start.cmd`，自动创建活动数据并为每个姓名和组织者生成 10 位随机 Token。
3. 从 `token.txt` 按姓名发放参与者 Token，组织者保管管理 Token。
4. 访问 http://localhost:7999。
5. 组织者使用管理 Token 登录，在设置中填写开始时刻和锁定间隔。
6. 参与者登录，调整倾向排列并确认。

自定义端口：

```powershell
.\start.cmd 7999
```

局域网用户通过服务器 IP 和对应端口访问。Windows 防火墙需允许该 TCP 端口。服务在当前终端运行，按 Ctrl+C 停止。

每次启动从 `options.txt` 和 `people.txt` 全量重建 `data.json`，并生成一套新的 Token 覆盖 `token.txt`。开始时刻和锁定间隔为空白，倾向排列恢复为选项文件顺序，确认记录和锁定结果为空。组织者重新设置时间，参与者使用新 Token 登录并确认排列。

Token 由大小写字母和数字组成，长度为 10，区分大小写，每个账户的 Token 唯一。姓名字符串完全一致的所有位置共用一个 Token，登录后可管理该姓名下的每个位置。

## 功能

- 当前情况：查看各选项的已锁定数量与总容量、下一位参与者、下一次锁定倒计时；人员列表按 `people.txt` 顺序逐行显示位置、姓名、组别和最近一次确认的首选项，未确认的位置显示“尚未选择”。
- 账户登录：使用 Token 登录和退出，每个姓名对应一个账户，每个位置对应一次选择机会。
- 设置：组织者设置开始时刻与锁定间隔；每个浏览器可设置亮色或暗色显示。
- 倾向排列：参与者切换自己的位置，通过上下箭头排列该位置所属组别的全部选项，点击“确认排列”保存并公开首选项。每次确认覆盖该位置的公开选择。
- 自动锁定：服务器按编号依次处理，选择排列中首个有余量且本人同组尚未锁定的选项。

## 锁定规则

第 1 位在开始时刻锁定，第 2 位在一个间隔后锁定。第 N 位的锁定时刻为：

```text
开始时刻 + (N - 1) × 锁定间隔
```

锁定间隔为 1 至 86400 的整数秒。组织者在开始前可修改设置，清空开始时刻可让活动处于待设置状态。活动开始时，全局设置锁定。

倾向排列初始顺序与选项文件一致，初始排列可直接点击确认。参与者在自己的锁定时刻前可重新排列并确认。同一用户名下同组各位置的确认首选项需互不重复，首选项与本人同组其他位置的锁定选项重复时会报错。

定时锁定从排列顶部依次查找有余量且本人同组尚未锁定的选项。全部选项满额或已被本人同组位置锁定时，结果记为“无可用选项”，下一位按照预定时刻处理。未确认的位置按初始排列参与定时锁定。账户区域显示当前所选位置的最终锁定结果，公开列表持续显示最近一次确认的首选项。不同用户可在容量范围内选择同一选项。

服务器每 250 毫秒检查到期任务。页面每 2.5 秒同步状态。关闭浏览器后服务器继续执行。每次启动创建一轮全新的活动，按输入文件中的人员顺序和组织者设置的时间执行。锁定记录中的时间为预定时刻。

设置输入使用组织者浏览器所在时区，各浏览器按本机时区显示时刻。锁定以服务器时钟为准。

## 输入文件

`options.txt` 每行填写 `选项名称 正整数容量 [组别]`，以空格或 Tab 分隔。组别支持中文、英文和数字字符串，省略时归入 `0` 组。组名连续书写，首字符需为 +、-、# 以外的字符。选项名称唯一且连续书写。可在首行使用 `@title` 设置页面标题。

```text
@title 座位选择
靠窗座位 2 安静组
安静区 2 安静组
讨论区 2
```

`people.txt` 每行严格填写 `姓名 组别` 两列，以空格或 Tab 分隔。每行对应一个位置，只能选择指定组别中的选项。姓名和组名按字符串精确匹配。

```text
张三 安静组
李四 安静组
王五 0
张三 0
```

- 每行必须指定一个实际存在的组别，列数错误、组别缺失或使用规则符号时会显示行号并报错。
- 同名位置可属于不同组别，每个位置独立保存排列并按顺序锁定。
- 总容量至少等于位置数，每个组别至少包含一个选项。

输入支持 UTF-8 BOM、Windows 换行和空行。每次启动完整读取两个输入文件，选项、容量、组名、人员及顺序均以文件为准。格式校验通过且端口监听成功后，写入重建的数据和新 Token。

## 数据与部署

`data.json` 保存设置、Token 哈希、排列和锁定结果。`token.txt` 包含姓名和 Token 两列，首条记录为管理员凭证，其余按姓名排列，同名账户输出一行。每次设置、排列和结果变更都会写入数据文件。

需要留存本轮结果时，在重启前备份 `data.json`。运行 `.\start.cmd` 即可重建并启动活动。`.\init.cmd` 可在 `data.json` 和 `token.txt` 均为空缺时提前生成初始数据。

部署时将项目文件夹复制到目标 Windows 电脑，包含 `node.exe`、`src/`、启动脚本及活动数据。

服务通过 `app.lock` 保持单进程写入，通过临时文件与原子替换保存数据。备份和搬迁前先停止服务。输入文件、凭证和数据文件由组织者保管，网页提供页面资源及状态接口。HTTP 用于受信任局域网；公网部署使用 HTTPS 反向代理和访问控制。
