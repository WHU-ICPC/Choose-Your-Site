# 顺序选择

仅面向 Windows。本目录已包含 `node.exe`，无需另行安装 Node.js 或配置 PATH，无第三方运行依赖，无需 `npm install`。所有源码（服务、页面、初始化逻辑和测试）位于 `src/`；根目录只保留启动入口、运行时、配置、输入及数据等文件。网页不依赖 CDN 或外部资源。

## 初始化

1. 修改 UTF-8 编码的 `options.txt` 和 `people.txt`。支持 Windows CRLF、UTF-8 BOM；忽略空行。
2. 在本目录终端运行 `.\init.cmd`。
3. 从生成的 `tokens.txt` 向每个人单独发送对应 Token。一个 Token 恰好代表一次选择；同一个人有多次机会，就在人员文件中写多行。

固定输入格式：

`options.txt`：开头可放标题和每人限时，其后每行 `选项名称 正整数容量`，用空格或 Tab 分隔。选项名称不重复，不能包含空白。

```text
@title 座位选择
@timeout 60
靠窗座位 2
安静区 2
讨论区 2
```

`@title` 后是项目标题，可以含空格，在页面顶部醒目显示；省略时为“顺序选择”。`@timeout` 后是每人允许选择的秒数，正整数表示限时；省略、`0` 或 `无限` 均表示不限时。这两行只能出现在选项之前，各最多一次。附带示例使用 `@timeout 0`，默认不限时。

计时从服务启动后轮到该人时开始，而非从登录开始。截止时，服务器从其允许且尚有余量的项目中等概率随机选择，即使无人打开页面也会执行。每人独立计时；重启不会重置已经开始的截止时间，停机时间也计入限时，重启后会依次补处理已超时的轮次。没有任何允许且有余量的项目时仍会阻塞，不能越权或超额分配。

标题和限时与选项一起在初始化时写入数据。已有 `data.json` 仍可直接使用，缺少新字段时按默认标题、不限时处理，不会重新发放 Token。修改 `options.txt` 不会自动修改已有活动；新活动请按下文流程备份重置。

`people.txt`：每行 `姓名 允许选项规则`，按行顺序编号，从 1 开始。姓名不含空白，可重复。规则中的名称对应 `options.txt`，不是编号。

```text
张三
李四 +靠窗座位 +安静区
王五 -讨论区
张三
赵六 +讨论区
```

- 姓名后没有规则：允许所有选项。
- `+选项名`：白名单，只允许列出的选项。
- `-选项名`：黑名单，排除列出的选项。
- 多个规则用空格或 Tab 分隔；同一行不能混用 `+` 和 `-`。
- 不存在的选项、重复选项名、无可选项目和总容量不足会导致初始化失败。

固定输出：

- `data.json`：顺序、权限、Token 哈希和已提交结果。每次成功提交立即持久化。
- `tokens.txt`：UTF-8 BOM 的表格文本，列为姓名、编号、Token。按中文姓名排序，同名按编号排序。此文件包含登录凭证，请妥善保管。

初始化不会覆盖已有 `data.json` 或 `tokens.txt`。需要重新开始时，先停止服务，备份并移走这两个文件，再运行初始化。旧 Token 随重置失效。修改输入文本不会改变已经初始化的活动。

## 启动

```powershell
.\start.cmd
.\start.cmd 8080
```

启动脚本只接受一个可选端口，默认 `7999`，始终使用本目录的 `node.exe` 并在当前终端前台运行，不创建后台服务。浏览器访问 `http://localhost:7999`；其他人使用服务器的局域网 IP，例如 `http://192.168.1.10:7999`。按 `Ctrl+C` 停止。

服务监听所有网卡。跨机器访问时，需要在 Windows 防火墙放行所选 TCP 端口；程序不会自动修改防火墙。端口占用会明确报错，不会擅自改端口。

打包部署：停止服务后，将整个文件夹（包含 `node.exe` 和 `src/`）复制或压缩到与内置 Node.js 架构兼容的目标 Windows 电脑，无需另外安装运行时。保留 `data.json` 即可继续原活动，无需再次初始化。不要通过网页、公共网盘或公开代码仓库发布包含 Token 和数据的部署包。

## 页面及规则

- 游客可以查看所有项目的剩余量/总量、按顺序排列的已选结果、当前等待的人。
- 登录后显示该 Token 的姓名、顺序及全部允许选项，满额项目仍然显示。
- 必须由当前编号提交；后面的人无法抢选。提交前有浏览器原生二次确认。
- 重复登录不会增加机会，已使用的 Token 只能查看结果。提交后不可撤销。
- 页面每 2.5 秒刷新；最终权限、顺序和余量以服务端校验为准。
- 未轮到时可保存私有预选择：从下拉框添加项目，用上下箭头排列优先级，用移除按钮删除项目。列表可包含部分或全部允许项目，不能重复。保存后、轮到前可继续更改，清空后保存即可取消；未保存的修改不生效。
- 轮到时立即依次检查已保存排列，自动选择第一个有余量的项目，并继续处理下一位。所有排列项目都满额或没有设置时，转为正常手动选择及限时流程。自动选择不再弹出确认窗口，关闭浏览器不影响已保存的预选择。预选择不会出现在公共 API 或其他人的登录数据中。
- 亮暗模式在本浏览器保存；登录凭证在当前标签页会话中保存，退出时清除。
- 如果当前参与者允许的选项全部满额，页面会提示联系组织者，且不会自动跳号。严格顺序和任意白名单组合可能产生这种阻塞，即使总容量足够。组织者应提前安排容量和权限；本版本不提供跳过或修改已选结果的管理入口。

## 数据与安全

服务端只公开四个静态资源及 API，不能通过 URL 下载输入、Token 或数据文件。页面使用文本节点显示姓名及项目名。Token 使用密码学随机数生成，服务数据只保存哈希；发放表保留原文。

单进程持有 `app.lock`，防止两个服务或初始化同时修改数据。异常结束后的残留锁会在确认原进程不存在时自动清理。若锁文件损坏或 PID 被其他进程复用，先确认服务已停止，再手动删除 `app.lock`。

提交采用临时文件写入、刷盘和原子替换，保存失败不会在内存中确认选择。不要在服务运行时手动修改数据。备份与搬迁前请先停止服务。

默认 HTTP 适用于受信任局域网，不会加密传输 Token。公网部署应由组织者配置 HTTPS 反向代理和访问控制。此工具没有自动证书、管理后台或账号找回功能。

## 测试

```powershell
.\node.exe --test src/test/*.test.mjs
```

测试覆盖解析、权限、越序提交、重复并发提交、容量、持久化恢复、私有文件访问和数据锁。测试使用本目录下临时目录，结束后自动清理，不修改正式活动数据。

可选浏览器测试（需要本机安装 Microsoft Edge）：

```powershell
npm ci
npm run test:browser
```

浏览器测试覆盖登录、等待、满额显示、原生确认取消/确定、会话恢复及桌面/手机布局，截图输出到 `verification`。Playwright 仅用于开发验证；上述安装命令需要开发机另有 npm，正常启动不需要 npm 或安装依赖。部署时可以省略 `node_modules`、`src/test` 和 `verification`。
